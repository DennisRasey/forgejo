When a review is submitted to Forgejo on a PR, the `commit_id` is never validated.  This can allow someone to submit a review on a pull request that was authored by a *trusted* author, but, provide a malicious review commit_id, and run a workflow from an arbitrary commit (including one from a forked pull request).  The fix is to align the `forgejo.ref` variable with the PR reference (refs/pull/%d/head), not the commit that the review was submitted on.  This is consistent with GitHub's behaviour (https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request_review).<!--description-->
