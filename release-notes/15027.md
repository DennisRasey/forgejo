fix: pull_request_review Actions can be triggered and run as trusted from arbitrary commits.  When a review is submitted to Forgejo on a PR, the `commit_id` is never validated.  This can allow someone to submit a review on a pull request that was authored by a *trusted* author, but, provide a malicious review commit_id, and run a workflow from an arbitrary commit (including one from a forked pull request).  The fix is to align the `forgejo.ref` variable with the PR reference (refs/pull/%d/head), not the commit that the review was submitted on.  This is consistent with GitHub's behaviour (https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request_review).
fix: consider visibility of users fetching watched and starred repositories
fix: nuget-based access token authentication does not respect token scopes.  Authenticating via `X-NuGet-ApiKey` with an access token does not respect the access token's scopes.  This authentication mechanism is limited to the package APIs, which does limit the scope of abuse to allowing an access token to access packages even if it doesn't have package scope access.  The issue has been fixed by fixing the missing scope return value to the authentication system, and reviewing other authentication methods for similar gaps.
